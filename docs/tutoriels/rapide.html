Tutoriel 1 · Environ 2 heures

Mode rapide : un prototype

Un salon de coiffure veut un carnet de réservations : les clients choisissent une prestation et un créneau libre, puis laissent leur nom et leur e-mail ; la coiffeuse voit les rendez-vous du jour. En un après-midi, vous allez en faire un prototype en ligne, à montrer et à essayer.

Le mode rapide va droit au but : une seule conversation pour décrire l'idée, puis Pulse réalise la prise de rendez-vous et la met en ligne. Il saute volontairement des étapes. Vous les retrouverez dans le tutoriel complet, qui reprend la même appli pour de vrais clients.

Vous tapez une commande, Pulse pose des questions, vous répondez avec vos mots. Les réponses montrées ici sont des exemples : donnez les vôtres.

0 Avant de commencer 10 minutes

Objectif : avoir un dossier vide, ouvert dans VS Code, avec le panneau Claude Code prêt et Pulse installé avec sa pile Next.js.

Ce tutoriel utilise VS Code avec l'extension Claude Code : vous discutez avec Claude dans un panneau, et vous voyez à côté les fichiers que Pulse écrit pour vous.

  1. Vérifiez que tout est installé avec la page Prérequis : Claude Code, Git, Node.js (22.19 ou plus), VS Code et son extension Claude Code, les plugins pulse et pulse-next, et un compte GitHub.
  2. Créez un dossier vide, par exemple carnet-reservations, là où vous rangez vos documents.
  3. Ouvrez VS Code. Dans le menu File (Fichier), choisissez Open Folder… (Ouvrir le dossier…), puis sélectionnez le dossier carnet-reservations. Les menus de VS Code sont en anglais au départ : c'est normal.
  4. Si VS Code demande « Do you trust the authors of the files in this folder? » (faites-vous confiance aux auteurs de ces fichiers ?), répondez Yes, I trust the authors : c'est votre propre dossier.
  5. Ouvrez le panneau Claude Code : cliquez sur ✻ Claude Code, en bas à droite de la fenêtre. Vous pouvez aussi cliquer sur l'icône en forme d'étincelle, dans la barre de gauche, puis démarrer une nouvelle conversation.
  6. Cliquez dans la zone de saisie du panneau : c'est là que vous taperez toutes les commandes /pulse:… de ce tutoriel.

Conseil : vous préférez le terminal ou Claude Desktop ? Tout le tutoriel fonctionne aussi : dans le terminal, placez-vous dans le dossier, lancez claude et tapez les mêmes commandes ; dans Claude Desktop, ouvrez l'onglet Code sur ce dossier.

Conseil : gardez une heure devant vous pour les étapes 1 à 4, puis une heure pour les étapes 5 et 6. Entre les deux, vous pouvez faire une pause : Pulse retrouve le fil tout seul.

Résultat attendu : le panneau Claude Code est ouvert à côté de votre dossier, et la commande /pulse:init apparaît dans la liste quand vous tapez /pulse dans sa zone de saisie.

Les commandes /pulse:… n'apparaissent pas

Les plugins ne sont pas installés, ou VS Code n'a pas été relancé après l'installation. Suivez la page Prérequis, puis fermez et rouvrez VS Code.

Je ne trouve ni « ✻ Claude Code » ni l'étincelle

L'extension n'est pas installée, ou VS Code ne l'a pas encore chargée. Ouvrez la palette de commandes (Ctrl + Maj + P, ou Cmd + Maj + P sur Mac), tapez Developer: Reload Window (recharger la fenêtre) et validez. Sinon, installez l'extension avec la page Prérequis.

Objectif : transformer votre idée en documents clairs (brief, PRD, user stories) grâce à quatre blocs de questions et un seul écran de validation.

Vous avez choisi le parcours express : la conversation continue d'elle-même, sans rien taper. La commande ci-dessous sert seulement à le relancer, par exemple après une pause. Le détail est sur la page /pulse:express.

3 Choisir les outils 25 minutes

Objectif : choisir la pile technique de l'appli, préparer le projet de départ et, si vous le voulez, le mettre en ligne dès aujourd'hui.

Toujours dans la même conversation, Pulse remplit lui-même ce qu'il sait déjà de vos besoins, pose les questions qui restent, puis compare 2 ou 3 options. Avec le plugin pulse-next installé, la pile Next.js de Pulse en fait partie : c'est l'option recommandée pour une appli web avec des données partagées, car son code de départ est déjà vérifié. Le détail est sur la page /pulse:tech.

Maintenant, on choisit les outils. Combien de rendez-vous par jour, à peu près ? → Une vingtaine

Option A : la pile Pulse Next.js (site, base de données à Francfort, hébergement Vercel). Code de départ vérifié, recettes prêtes : c'est l'option qui demande le moins d'essais pour obtenir un code juste. (Recommandé) Option B : un formulaire en ligne relié à un tableur. Plus simple, mais sans vraie protection des données ni espace réservé. À savoir : l'offre gratuite de Vercel est réservée à un usage non commercial ; pour un vrai salon, il faudra l'offre payante.

Ce que vous faites à la main

Pulse vous guide pas à pas, un écran à la fois. Trois choses relèvent de vous :

  1. Un compte Neon (la base de données) sur console.neon.tech, avec un projet en région Francfort et une deuxième base pour le travail (la branche dev). Pulse vous dit quelle adresse copier, et dans quelle ligne de votre fichier .env.
  2. Un compte Vercel (l'hébergeur) sur vercel.com, relié à votre compte GitHub.

Pulse propose ensuite de mettre en ligne la page de départ, presque vide. Acceptez : vous découvrez aujourd'hui les réglages de l'hébergeur, avec une page simple, plutôt qu'à la fin avec tout le projet en jeu.

5 Réaliser la prise de rendez-vous 35 minutes

Objectif : faire construire l'écran de réservation, tâche par tâche, puis l'essayer vous-même.

Repartez d'abord d'une conversation neuve : elle sera plus légère, et Pulse retrouve tout dans les documents et la mémoire du projet. Dans le panneau Claude Code, tapez /clear. Si cette commande n'apparaît pas dans la liste qui s'affiche quand vous tapez /, ouvrez plutôt une nouvelle conversation : Ctrl + Maj + Échap (Cmd + Maj + Échap sur Mac) l'ouvre dans un nouvel onglet. Puis lancez la réalisation de la première user story :

/pulse:spirc -a US-001

/pulse:spirc enchaîne tout le travail d'une user story : il décrit précisément ce qu'elle doit faire (la spec), la découpe en petites tâches (le plan), puis fait réaliser chaque tâche par un assistant, relire et vérifier par deux autres qui n'ont pas écrit le code, et l'enregistre. L'option -a (autonome) enchaîne les tâches sans s'arrêter entre elles : vous testez tout en une fois, à la fin. Le détail est sur la page /pulse:spirc.

Même en autonome, Pulse s'arrête pour vos décisions : les questions sur le besoin, la validation de la spec et du plan, et les actions à faire à la main.

/pulse:spirc -a US-001

Je fais travailler des assistants spécialisés : l'un explore, l'un réalise, d'autres relisent et vérifient sans avoir écrit le code. Vous testerez toutes les tâches ensemble, à la fin. Avant le plan, deux questions sur la prise de rendez-vous : Combien de temps dure un créneau ? → Selon la prestation : coupe 30 min, couleur 1 h 30 Si deux clients choisissent le même créneau en même temps ? → Le premier l'obtient, le second voit un message (Recommandé)

La spec est prête. Valider (la spec ne bougera plus) ?

Le plan : T1 – Les prestations et les horaires du salon · T2 – Afficher les créneaux libres · T3 – Réserver un créneau · T4 – Confirmer la réservation à l'écran. Le plan vous convient ?

Oui

J'ai pris les réglages conseillés : je code en coulisse · tests selon la pile · envoi : directement sur la version principale. Dites-le si vous préférez autre chose. T1 ✅ terminée · US-001 : 1/4 … T4 ✅ terminée · US-001 : 4/4

🧪 À vous de tester, en un seul parcours : ouvrez http://localhost:3000, choisissez « Coupe », un créneau de demain, saisissez un nom et un e-mail, puis réservez. Les tests sont-ils concluants ?

Les numéros et titres des tâches ci-dessus sont un exemple : votre plan peut différer. Pendant la réalisation, Pulse peut vous demander une action à la main, par exemple accepter la création d'une clé secrète pour le formulaire. Claude Code vous demande alors l'autorisation : la clé est créée sans jamais s'afficher.

Ce que vous testez vous-même

  • Réserver une coupe sur un créneau libre : un message confirme la réservation.
  • Revenir à la liste des créneaux : celui que vous venez de prendre n'apparaît plus.
  • Envoyer le formulaire sans nom, ou avec un e-mail mal écrit : un message clair explique quoi corriger.
  • Recommencer sur votre téléphone, si possible : les boutons restent faciles à toucher.

Résultat attendu : vous avez réservé un créneau sur http://localhost:3000 ; Pulse affiche un tableau récapitulatif où chaque tâche est relue, testée et enregistrée.

Conseil : vous préférez voir et tester chaque tâche l'une après l'autre ? Lancez /pulse:spirc US-001, sans -a : c'est plus lent, et plus instructif.

Conseil : la vue de la coiffeuse, « Voir les rendez-vous du jour », se construit de la même façon avec /pulse:spirc -a US-002. Elle ajoute la connexion de la coiffeuse : comptez 30 à 45 minutes de plus. Vous pouvez la faire maintenant ou après la mise en ligne.

7 Et maintenant ? 5 minutes

Objectif : savoir ce que le mode rapide a laissé de côté, et quand passer au mode complet.

Votre prototype fonctionne et il est en ligne. Pour aller vite, le mode rapide a sauté exprès plusieurs étapes :

  • Les entretiens approfondis : l'idée, la première version et chaque user story ont été décrites en une seule conversation, au lieu d'un entretien chacune.
  • Les maquettes d'écrans : plusieurs versions de chaque écran, à comparer avant de construire.
  • Le test après chaque tâche : en autonome, vous avez tout testé en une fois, à la fin.
  • Les autres user stories : l'annulation, le rappel par e-mail et la suite de la liste.
