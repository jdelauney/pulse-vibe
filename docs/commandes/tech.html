Étape 2 · Décrire

/pulse:tech

Choisir la pile technique à partir du besoin (ou documenter celle d'un projet existant), comparer 2 à 3 options vérifiées sur la documentation officielle, et produire docs/technical.md, le bloc Pile technique de CLAUDE.md, la mémoire technique et la mise en place.

    Description

    Cette commande choisit avec vous les outils de votre appli : le langage, l'endroit où sont gardées les données, la connexion des utilisateurs, l'hébergement. On appelle cet ensemble la pile technique. Pulse joue le rôle d'un architecte qui parle simplement : « On comprend d'abord le besoin, et on choisit les outils après. Le plus simple qui répond au besoin est le meilleur choix. »

    Dans un projet neuf, Pulse lit votre brief et votre PRD, pose seulement les questions qui restent, puis construit 2 ou 3 options vraiment différentes. Des assistants vérifient chacune en parallèle sur la documentation officielle et les pages de prix. Vous voyez un tableau, une recommandation, et vous choisissez.

    Dans un projet qui a déjà du code, Pulse décrit simplement les outils déjà utilisés, avec les manques constatés, et vous demande de confirmer. Dans les deux cas, il peut ensuite préparer le code de départ, et même mettre en ligne une première page dès aujourd'hui.

➡️ Je recommande A : c'est l'option qui demande le moins d'essais.

    Pourquoi l'utiliser

    • Des outils adaptés à votre besoin. Chaque proposition part de votre projet, plutôt que d'une habitude ou d'une mode.
    • Des faits vérifiés. Une offre gratuite, un prix ou une limite sont affirmés seulement après vérification sur la source officielle ; ce qui reste invérifiable est signalé.
    • Une seule référence pour la suite. docs/technical.md guide ensuite la spec, le plan et le code.
    • En ligne dès le premier jour. Mettre en ligne une page presque vide, c'est découvrir aujourd'hui les réglages de l'hébergeur, plutôt qu'à la fin, avec tout le projet en jeu.

    Avec le pack Next.js : si le pack pulse-next est installé, sa pile devient une option du tableau : « code de départ vérifié, recettes prêtes et pièges connus déjà traités ». Pulse la recommande quand votre projet a des écrans, des comptes ou des données partagées ; pour une simple page vitrine, il vous dit qu'elle est trop lourde. Une fois choisie, le projet de départ se pose d'une seule commande, et les recettes (connexion, listes, e-mails, fichiers, paiement, langues, limite, référencement) seront reprises par la spec et le plan. Sans le pack, Pulse vous signale qu'il s'installe avec /plugin install pulse-next@pulseia.

    Comment la lancer

    /pulse:tech [contrainte ou préférence technique (facultatif)]

    Entre crochets [ ] : facultatif. Entre chevrons < > : à remplacer par votre valeur. La barre | sépare les choix possibles.

    • Sans rien : Pulse part de votre brief et de votre PRD.
    • Une contrainte ou une préférence (facultative) : elle guide les options proposées, par exemple un hébergement en France ou une technologie que vous connaissez déjà.
    /pulse:tech
    /pulse:tech "données hébergées en France"

    Si vous acceptez « Préparer le code de départ maintenant », Pulse installe les fichiers de départ de la pile, vérifie que l'appli se lance sur votre ordinateur et applique votre apparence si docs/design.md existe. Une décision difficile à défaire (où sont gardées les données, comment on se connecte) peut aussi devenir un fichier de décision.

    Risques et précautions

    • Le choix vous appartient. Pulse recommande, en donnant sa raison ; vous choisissez parmi les options, ou demandez à revoir un besoin.
    • Vos fichiers sont gardés. Pendant la préparation du code de départ, CLAUDE.md, README.md et .gitignore sont complétés, jamais écrasés.
    • La mise en ligne attend votre accord, puis Claude Code vous demande d'autoriser l'enregistrement et l'envoi vers votre dépôt en ligne.
    • Un paiement reste en mode test : cartes de test, transactions fictives. Le passage en mode réel est votre décision, au moment de la mise en ligne.

    Risque : une clé secrète écrite dans la conversation peut être lue et recopiée. Pulse vous guide pour la saisir vous-même, directement dans le fichier local .env. Gardez-la toujours hors de la conversation.

    Attention : une offre gratuite a ses limites. Avec le pack Next.js, Pulse vous prévient que l'offre gratuite de Vercel est réservée à un usage non commercial : un site qui vend ou fait la promotion d'une activité demande l'offre payante.

    Problèmes et solutions

    Pulse me dit qu'il manque le PRD

    Le PRD décrit la première version, qui guide le choix. Lancez /pulse:prd ; vous pouvez aussi continuer sans, Pulse le signalera dans ses choix.

    Pulse me signale une contradiction

    Deux de vos réponses ne vont pas ensemble, par exemple « paiement en ligne » avec « budget 0 € et aucun compte ». Tranchez : Pulse construit ensuite les options sur votre réponse.

    Aucune option ne passe la vérification

    Pulse vous explique le blocage commun et revient aux besoins. Assouplir une contrainte (budget, hébergement) ouvre souvent de nouvelles options.

    J'avais déjà fait mes choix techniques

    Pulse vous demande s'il faut les revoir (un besoin a changé) ou les garder. Gardez-les si rien n'a bougé.

    Je préfère installer le code de départ plus tard

    Choisissez « Plus tard, avec la première tâche » : la mise en place se fera alors comme première tâche du premier plan.

    Commandes liées

    • /pulse:prd : décider de la première version, qui guide le choix.
    • /pulse:ui : l'étape suivante, facultative, pour choisir l'apparence.
    • /pulse:us : écrire les user stories.
    • /pulse:deploy : mettre le site en ligne et le tenir à jour.
    • /pulse:cicd : un contrôle automatique à chaque envoi, une fois le dépôt en ligne relié.
    • /pulse:secrets : savoir où sont vos clés et les renouveler.
