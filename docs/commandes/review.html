/pulse:review

Relecture et vérification indépendantes d'une tâche (critères d'acceptation, sécurité, essai de l'application en marche), test manuel, puis corrections.

    Description

    /pulse:review fait examiner une tâche par deux assistants qui ne l'ont pas écrite. L'un relit le code : critères d'acceptation, sécurité, qualité. L'autre lance l'application et essaie chaque critère. « Un regard extérieur repère les oublis, et un essai en marche prouve que ça fonctionne ; votre test manuel le confirme ensuite. »

    Vous recevez un verdict, le nombre de remarques par gravité (Critique, Haute, Moyenne, Basse) et les trois plus importantes, traduites en langage simple : ce que ça change pour vos clients. Puis c'est à vous : Pulse vous donne les étapes du test et vous demande s'il est concluant.

    Enfin, Pulse corrige les remarques Critique, Haute et Moyenne, et les remarques Basse qui se confirment dans le code. Après chaque correction, une relecture de contrôle vérifie le résultat ; deux cycles de correction au plus.

    Le résumé présenté après l'examen d'une tâche.

    Pourquoi l'utiliser

    • Un regard neuf. Ceux qui examinent n'ont pas écrit le code : ils voient ce que l'auteur ne voit plus.
    • La preuve que ça marche. L'application est lancée et chaque critère essayé, au-delà d'une simple lecture.
    • Votre test compte. Une tâche est prête seulement quand vous l'avez testée vous-même.
    • Des corrections ciblées. Les remarques sont triées par gravité, et chaque décision est notée dans le rapport.

    • Pour tout le projet, avec tout : une relecture de l'ensemble par rapport à toutes les US terminées.

    Conseil : avec /pulse:spirc, ou /pulse:implement sans numéro de tâche, inutile de lancer cette commande : la relecture et votre test font partie de leur boucle.

    Comment la lancer

    /pulse:review [T3 | <US-XXX> | tout]

    Entre crochets [ ] : facultatif. Entre chevrons < > : à remplacer par votre valeur. La barre | sépare les choix possibles.

    • T3 : cette tâche, cherchée dans tous les plans (chaque numéro est unique).
    • Une US (US-003) : toutes ses tâches en cours, examinées en même temps, avec un rapport et un test par tâche.
    • tout : l'ensemble du projet, par rapport à toutes les US terminées. Seule la relecture du code se fait ici ; l'essai en marche se fait tâche par tâche.
    • Rien : la tâche en cours. S'il n'y en a aucune, ou plusieurs, Pulse vous demande laquelle.
    /pulse:review T3
    /pulse:review US-001
    /pulse:review tout

    Risques et précautions

    • Pour essayer l'application, un assistant la démarre puis l'arrête. Claude Code vous demande votre accord : Pulse vous l'annonce d'avance.
    • Vous choisissez quoi corriger. Pulse propose « Corriger Critique, Haute, Moyenne et les Basses retenues (Recommandé) », « Seulement les Critiques » ou « Je regarde d'abord ».
    • Accepter une réserve est possible. Si vous acceptez un point ⚠️ sans correction, c'est noté dans le rapport.

    Attention : un test « non concluant » compte comme une remarque Critique. Pulse corrige, puis vous refaites le test.

    Problèmes et solutions

    « Il n'y a rien à relire »

    Aucun changement ni tâche en cours. Réalisez d'abord une tâche avec /pulse:implement US-001.

    Je ne sais pas comment tester

    Suivez les étapes données par Pulse : elles commencent par ce que l'assistant n'a pas pu prouver seul, et indiquent comment ouvrir l'appli sur votre ordinateur.

    Mon test ne marche pas

    Répondez « Non, il y a un problème », puis décrivez ce que vous voyez, avec vos mots. Pulse le traite comme une remarque Critique, corrige, puis vous redonne le test.

    Le problème persiste après deux corrections

    Pulse s'arrête, l'explique simplement et le note dans le rapport. Lancez /pulse:get-help : vous obtenez une demande d'aide prête à envoyer.

    Commandes liées

    • /pulse:implement : réalise la tâche à relire.

    • /pulse:security : un contrôle complet de la sécurité, au-delà d'une tâche.
    • /pulse:test : lancer tous les tests automatiques du projet.
