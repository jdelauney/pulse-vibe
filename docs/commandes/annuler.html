/pulse:annuler

Revenir en arrière sans rien perdre : abandonner les changements en cours, annuler une tâche enregistrée, revenir à une version précédente, ou récupérer ce qui a été annulé ; aperçu et accord avant toute opération.

    Description

    Une tâche a tout cassé ? Vous voulez repartir de la version d'hier ? Cette commande vous ramène en arrière, sans rien perdre. Annuler ne gomme rien : Pulse ajoute une nouvelle version qui défait l'ancienne, ou met vos changements de côté. Vous pourrez toujours récupérer ce qui a été annulé.

    Elle sait faire quatre choses : abandonner les changements pas encore enregistrés, annuler une tâche enregistrée (ou toute une user story), revenir à une version précédente, et récupérer ce qui avait été annulé.

    Avant toute opération, Pulse vous montre un aperçu : ce qui sera défait, ce que cela apportait à l'appli, et ce qu'annuler ne défait pas. Rien ne se passe sans votre accord.

    Pourquoi l'utiliser

    • Vous ne perdez rien. Chaque annulation est elle-même réversible : relancez la commande et choisissez « Récupérer ».
    • Vous voyez avant d'agir. L'aperçu liste les tâches défaites, ce qu'elles apportaient et leurs fichiers.
    • Vos plans restent à jour. Une tâche annulée repasse à « à faire » dans son plan, avec une ligne de journal.
    • Pas besoin de connaître Git. Pulse vous présente vos versions en langage simple : « hier 17 h – T4 : permet de cocher un rendez-vous honoré ».

    Conseil : si un seul petit détail ne va pas, une correction est souvent plus simple qu'une annulation : essayez d'abord /pulse:fix.

    Comment la lancer

    /pulse:annuler [T3 | US-003]

    Entre crochets [ ] : facultatif. Entre chevrons < > : à remplacer par votre valeur. La barre | sépare les choix possibles. Facultatif : la tâche ou l'US à annuler.

    • Une tâche, par exemple T3 : Pulse annule cette tâche enregistrée.
    • Une user story, par exemple US-003 : Pulse annule toutes ses tâches enregistrées, en une seule fois (un aperçu, un accord, une nouvelle version).
    • Rien : Pulse demande « Que voulez-vous annuler ? » et vous propose les choix possibles : abandonner les changements en cours, annuler une tâche enregistrée, revenir à une version précédente, ou récupérer quelque chose que vous avez annulé.

    /pulse:annuler US-003
    /pulse:annuler

    Ce qu'elle produit

    CasCe qui est créé ou modifié
    Abandonner les changements en coursLes changements sont mis de côté dans Git, sous un nom qui commence par pulse-annuler, avec la date. Une tâche en cours dont tout est mis de côté repasse à « à faire ».
    Annuler une tâche ou une user storyUne nouvelle version qui défait la tâche (revert(T3): …). Dans le plan, la tâche repasse à « à faire », avec une ligne de journal.
    Revenir à une version précédenteUne copie de l'état actuel, sous le nom sauvegarde/ suivi de la date, puis une nouvelle version qui revient à la version choisie. Les plans sont mis à jour.
    RécupérerCe qui avait été mis de côté revient, ou une nouvelle version rétablit les tâches annulées.

    Les rapports de relecture restent en place. Pour une tâche ou une version, le travail est ensuite envoyé vers votre dépôt en ligne, comme après chaque tâche.

    Risques et précautions

    • Rien ne se fait sans votre accord. Une réponse floue vaut « Ne rien faire » : Pulse le dit et s'arrête.
    • Les tâches plus récentes sont signalées. Si elles touchent les mêmes fichiers, elles pourraient ne plus fonctionner : Pulse propose de les annuler aussi, ou de s'arrêter.
    • L'envoi n'écrase jamais le dépôt en ligne. C'est toujours un envoi simple, jamais forcé. Claude Code vous demande l'autorisation pour cet envoi.
    • Si votre site est en ligne et se met à jour automatiquement, l'envoi le remet dans l'état choisi. Pulse vous le rappelle.

    Attention : annuler ne défait que le code et les documents du projet. Un schéma appliqué dans la console de la base, des rendez-vous saisis sur le site en ligne, des variables saisies chez l'hébergeur ou un compte créé sur un service restent tels quels. Pulse les nomme dans l'aperçu et explique comment les défaire à la main.

    Problèmes et solutions

    Pulse dit qu'une opération est déjà en cours

    Une annulation ou une fusion précédente s'est arrêtée en route. Pulse vous l'explique et propose de l'interrompre proprement avant toute chose. Si une autre session de Claude Code travaille sur ce projet, l'opération est peut-être la sienne : terminez-la dans cette session.

    « Une tâche plus récente a modifié les mêmes lignes de code »

    Pulse ne peut pas défaire cette tâche toute seule. Il remet tout dans l'état d'avant, sans rien perdre, et propose /pulse:get-help pour préparer une demande d'aide.

    Je veux récupérer ce que j'ai annulé

    Relancez /pulse:annuler et choisissez « Récupérer quelque chose que j'ai annulé ». Pulse vous montre ce qui peut revenir. Pour repartir d'une copie sauvegarde/, l'opération est délicate : Pulse propose /pulse:get-help.

    Pulse ne me propose que certains fichiers à abandonner

    Une autre session de Claude Code travaille sur ce projet : certains changements sont peut-être les siens. Nommez seulement les fichiers que vous voulez mettre de côté.

    Pulse me renvoie vers /pulse:init

    Votre dossier n'a pas encore d'historique de versions. Il n'y a donc rien à annuler : lancez /pulse:init pour le créer.

    Annuler

    git revert --no-commit 4f2a9c1

    C'est fait : T3 est annulée par la version « revert(T3): annule le choix du créneau ». Elle repasse à « à faire » dans le plan. Pour la récupérer : relancez /pulse:annuler et choisissez « Récupérer ». ➡️ Prochaine étape : /pulse:implement US-001 T3 pour la refaire autrement.

    Abandonner les changements en cours

    Fichiers modifiés : - src/liste-du-jour.js : la liste des rendez-vous du jour - src/styles.css : les couleurs du carnet → Tout abandonner · Seulement certains fichiers

    Tout abandonner

    C'est fait : vos changements sont mis de côté sous « pulse-annuler 2026-10-10 14:32 liste du jour ». Ils peuvent revenir à tout moment avec « Récupérer ».

    Commandes liées

    • /pulse:status : voir où en est le projet après une annulation.
    • /pulse:implement : refaire autrement une tâche annulée.
    • /pulse:fix : corriger une erreur précise, plutôt que tout annuler.
    • /pulse:get-help : demander de l'aide quand l'annulation bloque.
    • /pulse:commit : enregistrer une version, pour pouvoir y revenir plus tard.
