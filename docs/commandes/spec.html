Étape 3 · Préparer

/pulse:spec

Rédiger la spécification d'une user story (une US = une spec, rangée à côté de son US) : l'intention seule, la solution étant laissée au plan : périmètre, hors objectifs, écrans, informations, règles, scénarios, « terminé quand » ; les points encore ouverts notés comme questions ; figée une fois validée.

    Description

    La spec décrit précisément ce que l'outil doit permettre pour une user story, du point de vue de l'utilisateur : les écrans, les informations, les règles, et ce qui doit se passer exemple par exemple. « La spec fixe ce que vous voulez obtenir ; le plan choisira comment le construire. »

    Pulse rédige d'abord un brouillon, sans rien inventer : chaque information vient de vos documents ou de vos réponses. Ce qu'il ne sait pas devient une question en suspens, notée à sa place. Il vous montre aussi ce qu'il propose d'ajouter (un message, une confirmation) : vous gardez ou vous retirez.

    Une fois validée, la spec est verrouillée : elle ne bougera plus. Un changement de besoin passera par une nouvelle user story et sa propre spec.

    US-001 · Prendre rendez-vous
Écrans      : les créneaux libres de la semaine · la confirmation
Informations: le rendez-vous (cliente, prestation, date et heure)
Hors objectifs : le paiement en ligne, le rappel par e-mail (US-003)
Terminé quand : une cliente réserve un créneau libre et le voit confirmé

Règle : un créneau se réserve une seule fois
  · Camille réserve mardi 14 h, libre
  · Inès essaie mardi 14 h, déjà pris

    Le résumé présenté avant la validation, suivi des titres des scénarios groupés par règle.

    Pourquoi l'utiliser

    • L'IA construit ce que vous voulez, pas ce qu'elle imagine. Rien n'est inventé : un trou devient une question qui vous est posée.
    • Les limites sont claires. Les hors objectifs disent ce que la user story laisse de côté.
    • Chaque critère est illustré. Des exemples concrets, avec des noms fictifs, couvrent le cas normal, les limites et les refus.
    • Vos données personnelles sont pensées dès le départ. Vous validez celles qui sont vraiment nécessaires, et qui a le droit de voir quoi.

    Avec le pack Next.js : quand la user story demande une connexion, une liste, des e-mails, des fichiers, un paiement, plusieurs langues, une limite ou la protection d'un formulaire ouvert à tous, la spec reprend les exemples prêts de la recette correspondante, reformulés avec vos mots.

    Comment la lancer

    /pulse:spec <US-XXX [US-YYY…] | "description de la demande">

    Entre crochets [ ] : facultatif. Entre chevrons < > : à remplacer par votre valeur. La barre | sépare les choix possibles.

    • Un numéro de user story (US-001) : la spec de cette user story.
    • Plusieurs numéros : une spec par user story, l'une après l'autre, chacune validée avant la suivante.
    • Une description entre guillemets : Pulse cherche la user story qui la couvre. Sinon, il en crée une nouvelle si votre PRD la prévoit ; hors PRD, il vous demande de la noter « En attente » ou de l'ajouter maintenant.
    • Sans rien : Pulse liste les user stories sans spec, la prochaine à réaliser en premier.
    /pulse:spec US-001
    /pulse:spec US-001 US-002
    /pulse:spec "ajouter un filtre par date"

    Risques et précautions

    • Cette commande écrit seulement des documents. Elle ne touche ni au code ni à votre site.
    • Chaque ajout de Pulse se tranche. Vous choisissez lesquels garder ; un ajout refusé sort de la spec.
    • La validation n'est proposée que sans question en suspens. Sinon, Pulse vous dit lesquelles restent et propose de garder la spec en brouillon.

    Attention : « Valider (la spec ne bougera plus) » verrouille la spec. Relisez les scénarios avant de répondre. Plus tard, un changement passera par une nouvelle user story, qui complète ou remplace l'ancienne.

    Problèmes et solutions

    Pulse me demande une demande plus précise

    Votre description ne dit pas qui agit, quoi faire ou quel résultat obtenir. Reformulez avec ces trois éléments, par exemple : « la coiffeuse filtre les rendez-vous par date pour voir sa semaine ».

    Je veux changer une spec déjà validée

    Elle est verrouillée. Pulse propose « Créer une nouvelle US qui la fait évoluer » : la nouvelle spec cite l'ancienne, et l'ancienne reçoit seulement la mention « remplacée par » si elle est remplacée.

    Je ne sais pas encore répondre à une question

    Gardez-la ouverte : elle reste notée dans la spec, qui reste en brouillon. Relancez /pulse:spec US-001 quand vous avez la réponse ; Pulse reprend par les questions en suspens.

    Pulse me propose de découper la user story

    Elle est de grande taille. Une spec couvre une user story de taille raisonnable : découpez-la avec /pulse:us, puis faites une spec pour chaque morceau.

    Pulse me renvoie vers /pulse:init

    Vos documents sont à l'ancien format. /pulse:init les range au nouveau format, puis relancez la spec.
