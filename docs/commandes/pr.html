Étape 4 · Construire

/pulse:pr

Travailler sur une version parallèle et proposer de la rassembler : créer la branche de travail, puis ouvrir sur le site du dépôt la proposition en brouillon, décrite à partir des commits, du plan et des relectures.

    Description

    Une branche, c'est une version parallèle de votre projet : vous y avancez sans toucher au site en ligne. Cette commande crée cette version parallèle avant que vous commenciez une user story, avec un nom clair, tiré du plan.

    Quand le travail est prêt, elle prépare la proposition de version parallèle sur le site du dépôt (GitHub ou GitLab). Elle rédige le titre et la description à partir de vos enregistrements, du plan et des rapports de relecture, vous les montre, puis ouvre la proposition en brouillon après votre accord. Vous pouvez la relire, la tester, puis l'accepter : votre travail rejoint alors la version principale.

    Proposition prête :
  Titre        Choisir un créneau libre dans le carnet
  Base         main, la version principale du dépôt
  Tâches       T1 à T4 du plan US-003
  Relecture    ✅ 4 tâches relues · secrets contrôlés

➡️ Ouvrir la proposition en brouillon (Recommandé) · Modifier le texte · Annuler

    Ce que /pulse:pr vous montre avant d'ouvrir la proposition.

    Pourquoi l'utiliser

    • Le site en ligne reste intact pendant le travail. Il change seulement quand vous acceptez la proposition.
    • La description est écrite pour vous. Ce qui change à l'usage, les tâches du plan, les étapes pour tester et l'état des relectures, en français.
    • Vous testez avant de publier. Si l'hébergeur le propose, une adresse de prévisualisation montre la nouvelle version, à part du site de vos clients.
    • Vous gardez la décision. Pulse ouvre la proposition en brouillon ; c'est vous qui l'acceptez, sur le site du dépôt.

    Conseil : au démarrage de /pulse:implement ou de /pulse:spirc, choisissez « Une version parallèle pour l'US, publiée quand vous l'acceptez sur le site du dépôt » : Pulse prépare alors la version parallèle et sa proposition pour vous. /pulse:pr sert à le faire à la main.

    Comment la lancer

    /pulse:pr [branche [<US-XXX>] | <branche de base>]

    Entre crochets [ ] : facultatif. Entre chevrons < > : à remplacer par votre valeur. La barre | sépare les choix possibles. Vide : ouvrir la demande pour la branche en cours.

    • branche suivi d'une user story : crée la version parallèle avant de coder. Pulse propose un nom tiré du plan, par exemple feat/us-003-choisir-creneau (fix/… pour une correction), et vous le faites valider. Sans user story, Pulse vous montre les plans existants et vous demande lequel choisir.
    • Sans argument : ouvre la proposition pour la version parallèle sur laquelle vous êtes.
    • Un nom de branche : ouvre la proposition vers cette version-là, au lieu de la version principale.
    /pulse:pr branche US-003
    /pulse:pr

    Ce qu'elle produit

    Aucun fichier de votre projet ne change. Tout se passe dans l'historique Git et sur le dépôt distant :

    ÉlémentÀ quoi il sert
    La version parallèle, par exemple feat/us-003-choisir-creneauRanger vos enregistrements à part, partie de la version principale à jour.
    La proposition en brouillon, sur le site du dépôtRelire, tester et accepter le travail. Sa description suit le modèle Pulse : type de changement, description, ce qui change à l'usage, tâches et user stories, étapes pour tester, relecture et sécurité.

    Si le dépôt a déjà son propre modèle de description, Pulse le reprend à la place du sien.

    Risques et précautions

    • Vous seul acceptez la proposition. Pulse l'ouvre en brouillon et vous laisse le bouton « Merge » du site du dépôt.
    • Chaque envoi passe par votre accord. Claude Code vous demande d'autoriser git push (l'envoi vers le dépôt distant) et git pull (la récupération de la dernière version). Pulse envoie toujours normalement, sans forcer.
    • Les secrets sont contrôlés avant l'envoi, comme avec /pulse:commit : fichiers de clés hors de Git, aucune clé dans les changements.
    • Rien ne se perd quand Pulse range vos enregistrements sur une nouvelle version parallèle : il vous l'explique, attend votre accord, puis vérifie qu'ils y sont bien.

    Attention : accepter la proposition met votre travail dans la version principale. Si la mise en ligne automatique est en place, le site change quelques minutes plus tard. Testez d'abord les « Étapes pour tester » sur l'adresse de prévisualisation.

    Problèmes et solutions

    « Des modifications ne sont pas enregistrées »

    Pulse vous propose /pulse:commit d'abord. Avant de créer une version parallèle, vous pouvez aussi choisir d'emporter ces modifications : elles suivent automatiquement.

    J'ai travaillé directement sur la version principale

    Si vos enregistrements ne sont pas encore envoyés, Pulse propose de les ranger sur une nouvelle version parallèle ; la version principale revient à l'état du dépôt en ligne. Tout est conservé. S'ils sont déjà envoyés, pensez à /pulse:pr branche la prochaine fois.

    L'outil du dépôt n'est pas installé ou pas connecté

    Pulse vous donne le lien à ouvrir sur le site du dépôt, puis le titre et la description à coller. Cochez « brouillon » (Draft) avant de valider. L'installation de l'outil reste à votre choix.

    L'envoi est refusé

    Le dépôt distant contient une version plus récente. Pulse vous l'explique, propose git pull pour la récupérer, puis réessaie l'envoi.

    Une proposition existe déjà pour cette version parallèle

    Pulse vous donne son adresse et garde une seule proposition. Pour la compléter, envoyez simplement vos nouveaux enregistrements avec /pulse:commit push : elle se met à jour toute seule.

    Ouvrir la proposition en brouillon

    Claude Code va vous demander l'accord pour envoyer : c'est ce qui met votre travail sur le dépôt distant.

    git push -u origin feat/us-003-choisir-creneau · gh pr create --draft --base main

    La proposition est ouverte en brouillon. Une adresse de prévisualisation apparaît dans la proposition : testez-y les « Étapes pour tester ». Quand tout va bien, cliquez sur « Merge » sur le site du dépôt.

    Commandes liées

    • /pulse:implement : réaliser les tâches sur la version parallèle.
    • /pulse:review : faire relire chaque tâche avant d'ouvrir la proposition.
    • /pulse:commit : enregistrer, et envoyer de nouveaux enregistrements sur une proposition ouverte.
    • /pulse:cicd : des contrôles automatiques sur chaque proposition, et la protection de la version principale.
    • /pulse:deploy : relier le projet à un dépôt en ligne, s'il n'en a pas encore.
