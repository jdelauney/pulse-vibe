/pulse:explain

Expliquer simplement un fichier, une fonction ou une ligne de code, avec une question pour vérifier.

    Description

    Vous ne comprenez pas un morceau du code de votre appli ? Pulse vous l'explique simplement. D'abord en une phrase : à quoi il sert, vu par la personne qui utilise l'appli. Puis bloc par bloc, avec un court extrait et des mots de tous les jours.

    Au passage, Pulse relie le code aux notions de base, avec une image : une variable est une boîte avec une étiquette, une condition est un aiguillage, une fonction est une recette qu'on peut réutiliser. À la fin, une question à choix vérifie que vous avez compris.

    Le but : apprendre à lire le code. C'est la compétence clé pour relire ce que l'IA écrit pour vous.

    Ce fichier sert à afficher la liste des rendez-vous du jour pour le salon.

Bloc 1 – Lire la date du jour
  const aujourdhui = new Date();
  → Une boîte nommée « aujourdhui » qui garde la date d'aujourd'hui.

Bloc 2 – Garder seulement les rendez-vous du jour
  ...
📘 Ajouté au lexique : constante

    Le début d'une explication par /pulse:explain : une phrase, puis bloc par bloc.

    Pourquoi l'utiliser

    • Vous comprenez votre propre appli. Chaque bloc est traduit en langage courant, avec un exemple pris dans votre code.
    • Vous vérifiez ce que vous avez retenu. Une question à choix termine l'explication, avec une correction bienveillante.
    • Votre lexique grandit tout seul. Chaque mot nouveau y est ajouté, et passe à « maîtrisé » quand vous répondez juste.
    • Votre code reste intact. Un problème repéré au passage vous est signalé en une ligne, sans rien toucher.

    Quand l'utiliser

    1. 1 Démarrer
    2. 2 Décrire
    3. 3 Préparer
    4. 4 Construire
    5. 5 Mettre en ligne
    6. 6 Être trouvé
    7. 7 À tout moment
    • L'IA vient d'écrire du code et vous voulez savoir ce qu'il fait avant de l'enregistrer.
    • Une ligne vous intrigue dans un fichier.
    • Vous vous posez une question précise : « pourquoi ce bouton attend avant d'afficher la liste ? ».
    • Vous relisez une tâche terminée, pour la comprendre avant de passer à la suivante.

    Conseil : /pulse:explain explique un morceau de code précis. Pour apprendre une notion en général (les fonctions, les conditions), utilisez plutôt /pulse:learn.

    Comment la lancer

    /pulse:explain [fichier | fichier:ligne | nom de fonction | question]

    Entre crochets [ ] : facultatif. Entre chevrons < > : à remplacer par votre valeur. La barre | sépare les choix possibles.

    • Un fichier : Pulse explique tout le fichier, en 10 blocs au plus.
    • Un fichier suivi de deux-points et d'un numéro de ligne : Pulse explique cette ligne précise.
    • Le nom d'une fonction : Pulse la trouve et l'explique ligne par ligne.
    • Une question, entre guillemets : Pulse y répond à partir de votre code.
    • Rien : Pulse vous propose le dernier fichier modifié, ou vous demande quoi expliquer.
    /pulse:explain src/rendez-vous.js
    /pulse:explain src/rendez-vous.js:42
    /pulse:explain "pourquoi la liste du jour met une seconde à s'afficher ?"

    Ce qu'elle produit

    Une explication à l'écran. Votre code n'est pas modifié. Un seul fichier peut changer :

    FichierÀ quoi il sert
    docs/lexique.mdVotre lexique personnel. Chaque mot nouveau y est ajouté, et Pulse le signale en une ligne (« 📘 Ajouté au lexique : … »). Un mot bien compris passe à « maîtrisé ».

    Risques et précautions

    • Votre code reste tel quel. La commande lit seulement.
    • Le lexique se met à jour sans question. Chaque ajout est annoncé : vous pouvez le relire et le corriger à la main.
    • Un bug ou un problème de sécurité repéré au passage vous est signalé, sans correction. Pulse propose /pulse:review pour s'en occuper.

    Problèmes et solutions

    Pulse m'explique un autre fichier que celui que je voulais

    Sans précision, Pulse propose le dernier fichier modifié. Relancez la commande avec le nom du fichier, ou avec le fichier et la ligne : /pulse:explain src/rendez-vous.js:42.

    L'explication est trop longue

    Un long fichier est découpé en 10 blocs au plus. Pour aller droit au but, donnez une ligne précise ou le nom d'une fonction.

    J'ai répondu faux à la question de fin

    C'est normal, et utile. Pulse vous explique pourquoi la bonne réponse est juste. Demandez-lui de réexpliquer le passage, ou travaillez la notion avec /pulse:learn.

    Pulse signale un problème dans le code

    Il le dit en une ligne sans rien changer. Lancez /pulse:review pour une relecture complète, ou /pulse:fix si vous voyez déjà une erreur.

    Exemples

    /pulse:explain src/liste-du-jour.js

    Ce fichier sert à afficher les rendez-vous du jour, pour que le salon voie qui arrive et à quelle heure. Bloc 1 : il lit la date du jour et la range dans une boîte nommée « aujourdhui » (une constante). Bloc 2 : il garde seulement les rendez-vous de cette date. C'est un filtre : on passe chaque rendez-vous dans un tamis. Bloc 3 : il trie les rendez-vous par heure, puis les affiche. 📘 Ajouté au lexique : filtre

    Question : que se passe-t-il s'il n'y a aucun rendez-vous aujourd'hui ? → La page affiche une erreur → La page affiche une liste vide → La page montre les rendez-vous de demain

    La page affiche une liste vide

    C'est exactement ça : le filtre ne garde rien, la liste est vide. Voulez-vous que j'explique autre chose ?

    /pulse:explain "pourquoi la liste du jour met une seconde à s'afficher ?"

    Votre page demande les rendez-vous au serveur, puis attend sa réponse. C'est comme commander au comptoir : vous attendez que le plat arrive avant de le servir. Dans src/liste-du-jour.js, ligne 8, le mot « await » veut dire justement « attendre la réponse ». 📘 Ajouté au lexique : requête

    Commandes liées

    • /pulse:learn : apprendre une notion en profondeur, avec exercices et révisions.
    • /pulse:review : faire relire le code quand un problème est repéré.
    • /pulse:fix : corriger une erreur précise.
    • /pulse:implement : la commande qui écrit le code que vous relisez.
