Étape 4 · Construire

/pulse:commit

Enregistrer une version dans Git : un sujet par commit, message clair, après contrôle des secrets ; option push pour l'envoyer.

    Description

    « Un commit est une photo datée de votre projet, avec une légende. » /pulse:commit enregistre l'état actuel de votre projet dans l'historique Git, avec un message clair. Vous pouvez toujours revenir à une photo précédente, avec /pulse:annuler.

    Avant d'enregistrer, Pulse vérifie qu'aucune clé secrète ne part avec la version, et que la tâche a bien été relue et testée par vous. Il trie ensuite vos changements par sujet : une photo par sujet.

    Avec push, la version est aussi envoyée sur le dépôt en ligne, après votre accord. Pour la tâche d'un plan, l'envoi suit le choix noté dans le plan.

    Fichiers : creneaux.js, prise-rdv.html, PLAN-SPEC-US-001-prise-de-rendez-vous.md
Message :  feat(T3): affiche les créneaux libres de la journée
           Réf. : US-001

a1b2c3d feat(T3): affiche les créneaux libres de la journée

    Les fichiers et le message montrés avant l'enregistrement, puis la version enregistrée : son identifiant court et sa légende.

    Pourquoi l'utiliser

    • Un retour en arrière toujours possible. Chaque version est une photo à laquelle vous pouvez revenir.
    • Vos clés restent protégées. Un garde-fou automatique bloque toute version qui contient un secret.
    • Un historique lisible. Un sujet par photo, et un message qui dit ce qui change.
    • Seulement du travail vérifié. Une tâche s'enregistre une fois relue et testée par vous.

    Quand l'utiliser

    1. 1 Démarrer
    2. 2 Décrire
    3. 3 Préparer
    4. 4 Construire
    5. 5 Mettre en ligne
    6. 6 Être trouvé
    7. 7 À tout moment
    • Après /pulse:review, quand le verdict est validé et votre test concluant.
    • Après un changement hors tâche (documents, mémoire du projet) : il s'enregistre toujours.
    • Avec push, quand vous voulez aussi envoyer la version sur le dépôt en ligne.

    Conseil : avec /pulse:spirc, ou /pulse:implement sans numéro de tâche, chaque tâche s'enregistre dans la boucle : inutile de lancer cette commande.

    Comment la lancer

    /pulse:commit [push] ["message"]

    Entre crochets [ ] : facultatif. Entre chevrons < > : à remplacer par votre valeur. La barre | sépare les choix possibles. Facultatifs.

    • Rien : Pulse trie vos changements, propose le message, puis enregistre.
    • push, en premier mot : enregistre, puis envoie la version sur le dépôt en ligne, après votre accord. Placé ailleurs, le mot fait partie du message.
    • Un message, entre guillemets : Pulse part du vôtre et l'ajuste à la convention, en vous le disant.
    /pulse:commit
    /pulse:commit push
    /pulse:commit "ajoute le bouton push"

    Le dernier exemple enregistre sans envoyer : « push » n'est pas le premier mot.

    Ce qu'elle produit

    QuoiCe qui change
    L'historique GitUne version par sujet, avec un message comme feat(T3): affiche les créneaux libres de la journée. Le premier mot dit le type de changement : feat une nouvelle fonctionnalité visible, fix une correction, style la présentation, refactor une réorganisation sans changement visible, chore l'entretien.
    aidd_docs/tasks/<groupe>/PLAN-SPEC-US-XXX-<nom>.mdLa tâche passe « terminée », avec une ligne dans le journal du plan. Le plan fait partie de la même version.
    .gitignoreComplété si votre fichier de clés n'y était pas exclu.
    Le dépôt en ligneAvec push, ou selon le choix d'envoi du plan : la version y est envoyée.

    Risques et précautions

    • L'envoi demande votre accord. Pulse l'annonce : « Claude Code va vous demander l'accord pour envoyer : c'est ce qui met votre travail sur le dépôt distant. »
    • Jamais d'envoi forcé. Si le dépôt en ligne a des changements plus récents, Pulse vous l'explique et propose de les récupérer d'abord (git pull), puis d'envoyer à nouveau.
    • Un contrôle qui refuse l'enregistrement n'est jamais contourné. Pulse corrige les fichiers concernés, 3 essais au plus, sinon il s'arrête et vous explique.
    • Un fichier modifié sans explication est laissé de côté par défaut, et vous est signalé.

    Attention : vous pouvez choisir « Enregistrer quand même » une tâche pas encore relue. Le journal du plan le note : « enregistrée sans relecture, à la demande de la personne ». Une tâche relue mais pas encore testée par vous, elle, attend votre test.

    Risque : sur la branche principale, l'envoi met votre site en ligne à jour, si le déploiement automatique est en place. Pulse vous le rappelle avant d'envoyer.

    Problèmes et solutions

    « Votre test de T3 manque encore »

    C'est votre test qui confirme que la tâche fonctionne. Lancez /pulse:review T3 : la commande reprend directement à votre test.

    Le garde-fou a bloqué l'enregistrement

    Une clé ou un mot de passe se trouvait dans les changements. C'est une protection : Pulse retire la clé du code, puis recommence. Si cette clé a déjà été envoyée en ligne, lancez /pulse:secrets fuite.

    L'envoi est refusé

    Le dépôt en ligne a des changements plus récents que les vôtres. Pulse propose de les récupérer d'abord, puis d'envoyer à nouveau ; il ne force jamais l'envoi.

    « Tout est déjà enregistré »

    Il n'y a aucun changement depuis la dernière version. Avec push, Pulse propose d'envoyer seulement les versions qui ne sont pas encore en ligne.

    La version reste « en local »

    Votre projet n'est relié à aucun dépôt en ligne. Pulse vous propose /pulse:init pour en relier un, ou /pulse:deploy.

    Exemples

    /pulse:commit push

    pulse-aidd revue T3

    T3 est relue, vérifiée et testée par vous : je l'enregistre. Fichiers : creneaux.js, prise-rdv.html et le plan de US-001. Message : feat(T3): affiche les créneaux libres de la journée (Réf. : US-001). « feat » signale une nouvelle fonctionnalité visible.

    git commit -m "feat(T3): affiche les créneaux libres de la journée" -m "Réf. : US-001"

    a1b2c3d feat(T3): affiche les créneaux libres de la journée : l'identifiant court de la photo, puis sa légende. Claude Code va vous demander l'accord pour envoyer : c'est ce qui met votre travail sur le dépôt distant.

    git push

    Envoyée sur main. ➡️ Prochaine étape : /pulse:spirc US-001, pour la suite du plan.

    /pulse:commit

    pulse-aidd revue T4

    Votre test de T4 manque encore : c'est lui qui confirme que la tâche fonctionne. ➡️ Lancez /pulse:review T4 : la commande reprend directement à votre test.

    Commandes liées

    • /pulse:review : la relecture et votre test, avant l'enregistrement.
    • /pulse:annuler : revenir à une version précédente.
    • /pulse:pr : proposer une version parallèle, une fois le plan terminé sur une branche de travail.
    • /pulse:deploy : mettre en ligne quand la première version est terminée.
    • /pulse:secrets : réagir si une clé a été vue ou envoyée.
