Lexique

A

API
La porte d'entrée qu'un service ouvre aux autres programmes. Votre appli s'en sert pour envoyer un e-mail ou encaisser un paiement. Voir : clé d'API.
assistant (en anglais : sous-agent, subagent)
Une IA séparée à qui Pulse confie un seul rôle : réaliser une tâche, relire le code, essayer l'appli, écrire les tests. Ceux qui relisent n'ont pas écrit le code. Voir : les assistants.

B

base de données (en anglais : database)
L'endroit où l'appli range ses informations pour les retrouver plus tard : les rendez-vous, les clientes, les comptes. Avec le pack Next.js, elle est chez Neon. Voir : Neon.
bibliothèque (en anglais : library, package)
Un morceau de code écrit par d'autres, qu'on ajoute à son projet au lieu de tout réécrire. On dit aussi « dépendance ». Voir : npm.
branche (en anglais : branch)
Dans ce wiki : une version parallèle. Une copie du projet où l'on avance sans toucher à la version principale, celle que le site publie. Voir : la version parallèle.
brief
Le premier document du projet : votre idée racontée simplement, comme une histoire. Voir : le brief, /pulse:brainstorm.

C

CD (de l'anglais continuous deployment)
Dans ce wiki : la mise en ligne automatique. Le site se met à jour tout seul à chaque envoi sur la version principale. Voir : /pulse:deploy.
CI (de l'anglais continuous integration)
Dans ce wiki : les contrôles automatiques. Le site du dépôt vérifie votre projet à chaque envoi : clés, tests, construction. Voir : les contrôles automatiques.
Claude Code
L'assistant de programmation d'Anthropic : vous lui parlez en français, il lit et écrit les fichiers de votre projet. Pulse s'y ajoute. La façon conseillée de l'utiliser est VS Code avec l'extension. Voir : Claude Code et Pulse.
Claude Desktop
L'application de bureau de Claude. Son onglet Code donne accès à Claude Code avec des boutons, sans terminal. Voir : les prérequis.
CLAUDE.md
Le fichier des règles de votre projet. Claude Code le relit au début de chaque session ; Pulse y recopie la mémoire du projet. Voir : la mémoire du projet.
clé d'API (en anglais : API key)
Un code secret qui permet à votre appli d'utiliser un service en votre nom. Elle se range dans le fichier .env, jamais dans le code. Voir : les clés secrètes.
commande (en anglais : slash command)
Un ordre qui commence par une barre oblique et qu'on tape dans Claude Code, comme /pulse:init. Voir : toutes les commandes.
commit
Dans ce wiki : une version enregistrée. Une photo datée de votre projet, avec une légende, à laquelle on peut toujours revenir. Voir : la version enregistrée, /pulse:commit.
construction (en anglais : build)
L'étape qui transforme le code en une appli prête à être mise en ligne. Si elle échoue, rien n'est publié.
contrôles automatiques
Un contrôle qualité qui tourne tout seul sur le site du dépôt, à chaque envoi. Une coche verte : tout va bien ; une croix rouge : à corriger. En anglais : CI. Voir : /pulse:cicd.
critère d'acceptation (en anglais : acceptance criteria)
Une phrase qui dit comment vérifier qu'une user story est bien réalisée : « Étant donné… lorsque… alors… ». Voir : la user story.

D

demande de fusion (en anglais : merge request)
Le nom donné sur GitLab à la proposition de version parallèle. Sur GitHub, on dit pull request.
dépendance (en anglais : dependency)
Une bibliothèque dont votre projet a besoin pour fonctionner. Voir : bibliothèque.
déploiement (en anglais : deployment)
Dans ce wiki : la mise en ligne. Publier une nouvelle version du site chez l'hébergeur. Voir : la mise en ligne, /pulse:deploy.
dépôt (en anglais : repository, repo)
Le projet avec tout son historique de versions. Le dépôt en ligne en est la copie sur un site comme GitHub : une sauvegarde et le point de départ de la mise en ligne. Voir : le dépôt en ligne.
dossier à part
Un deuxième dossier du projet, sur sa propre version parallèle, pour qu'une deuxième session de Claude Code avance sans gêner la première. En anglais : worktree. Voir : la version parallèle et le dossier à part.

E

.env (fichier)
Le fichier où vous rangez vos clés secrètes, sur votre ordinateur seulement. Il n'est jamais enregistré dans l'historique, et Pulse empêche l'IA de le lire. Son modèle sans valeurs s'appelle .env.example. Voir : les clés secrètes.
epic
Dans ce wiki : un groupe de user stories, qui réunit celles d'un même grand besoin, comme « Gérer les rendez-vous ». Voir : la user story et ses groupes.
extension
Un module qu'on ajoute à un logiciel. L'extension Claude Code ajoute un panneau de discussion à VS Code. Voir : les prérequis.

F

fusion (en anglais : merge)
Rassembler le travail d'une version parallèle dans la version principale. C'est ce qui se passe quand vous acceptez une proposition sur le site du dépôt.

G

garde-fou
Une protection de Pulse qui examine chaque action de l'IA. Elle refuse ce qui est dangereux et demande votre accord pour ce qui est sensible, toujours avec la raison. Voir : les garde-fous.
Git
Le logiciel qui garde l'historique des versions de votre projet, sur votre ordinateur. Voir : la version enregistrée.
GitHub
Le site le plus répandu pour ranger un dépôt en ligne. GitLab en est un autre. Voir : le dépôt en ligne.
glossaire
La liste des mots du métier de votre projet, avec leur définition commune (« prestation », « créneau »). Il fait partie de la mémoire du projet. À ne pas confondre avec ce lexique, qui explique les mots techniques.

H

hébergeur (en anglais : hosting)
Le service qui fait tourner votre appli sur ses ordinateurs, jour et nuit, à une adresse web. Par exemple Vercel. Voir : la mise en ligne.
historique (en anglais : history, log)
Toutes les versions enregistrées de votre projet, mises bout à bout, de la plus ancienne à la plus récente.
hook
Un petit programme que Claude Code lance tout seul à certains moments : à l'ouverture d'une session, avant une action. Les garde-fous et le chargement de la mémoire de Pulse en sont.

J

jeton (en anglais : token)
Un code secret qui prouve votre identité auprès d'un service, comme une clé d'API. Il se range dans .env. Voir : clé d'API.

L

lint, linter
Un outil qui relit le code automatiquement et signale les erreurs de forme et les oublis courants, comme un correcteur d'orthographe pour le code. Il fait souvent partie des contrôles automatiques.
localhost
L'adresse de votre propre ordinateur, par exemple http://localhost:3000. Vous y voyez votre appli pendant le travail, avant la mise en ligne. Vous seul y avez accès.

M

main
Le nom habituel de la version principale du projet, celle que le site publie. Voir : version principale.
Markdown
Une façon simple d'écrire du texte mis en forme, avec des signes comme # pour un titre. Les documents de Pulse (brief, PRD, spec…) sont écrits ainsi, dans des fichiers qui finissent par .md.
mémoire du projet
Quelques fichiers courts qui rappellent à l'IA, à chaque session, vos choix, les mots de votre métier et les pièges déjà rencontrés. Voir : la mémoire du projet, /pulse:memory.
merge
Voir : fusion.
migration
Un changement de la forme de la base de données, écrit dans un fichier : une nouvelle information à garder, un nouveau tableau. Il s'applique d'abord à la base de travail, puis à celle du site en ligne.
MoSCoW
La méthode qui range les fonctionnalités en quatre catégories. Dans ce wiki : Indispensable, Essentiel, Optionnel, En attente. Voir : le PRD.
MVP (de l'anglais minimum viable product)
Dans ce wiki : la première version. La plus petite appli réellement utilisable par de vrais utilisateurs : toutes les fonctionnalités Indispensables, et elles seules. Voir : le PRD et la première version.

N

Neon
Un service qui héberge votre base de données en ligne. Le pack Next.js l'utilise, avec une base pour le travail et une autre pour le site en ligne. Voir : les prérequis.
Next.js
Un ensemble d'outils pour construire des sites et des applis web. C'est la base du pack Next.js de Pulse. Voir : le pack Next.js.
Node.js
Un logiciel qui fait tourner des programmes écrits en JavaScript sur votre ordinateur. Pulse en a besoin pour ses garde-fous. Voir : les prérequis.
npm
L'outil, livré avec Node.js, qui installe les bibliothèques d'un projet. Une commande comme npm install les télécharge.

P

pack de pile
Un complément de Pulse qui apporte le savoir-faire d'un ensemble d'outils précis : un projet de départ, des conseils, des recettes. Le pack Next.js s'appelle pulse-next. Voir : le pack Next.js.
pile technique (en anglais : stack)
L'ensemble des outils choisis pour votre appli : le langage, la base de données, la connexion des utilisateurs, l'hébergeur. Voir : /pulse:tech.
plan
Le document qui décide comment construire ce qu'une spec demande, découpé en tâches numérotées. Voir : le plan, /pulse:plan.
plugin
Un module qu'on installe dans Claude Code pour lui ajouter des commandes et des protections. Pulse est un plugin. Voir : les prérequis.
PR
L'abréviation de pull request.
PRD (de l'anglais product requirements document)
Le document de besoin produit : la vision, les utilisateurs, les objectifs et le contenu de la première version. Voir : le PRD, /pulse:prd.
première version
La plus petite appli réellement utilisable par de vrais utilisateurs. En anglais : MVP.
prévisualisation (en anglais : preview)
Une copie de votre site, publiée par l'hébergeur à une adresse provisoire, pour essayer une version parallèle avant de l'accepter. Le site principal n'est pas touché.
projet de départ (en anglais : starter, boilerplate ; dans les fichiers de Pulse : squelette)
Le code de base, déjà vérifié, posé au début du projet : une page d'accueil, le thème, la configuration, les premiers tests. Le pack Next.js le fournit.
proposition
La demande, sur le site du dépôt, de rassembler une version parallèle dans la version principale. Vous la relisez puis vous l'acceptez. Voir : pull request, /pulse:pr.
pull request
Dans ce wiki : la proposition de version parallèle, sur GitHub. Sur GitLab : demande de fusion. Voir : la version parallèle.
push
Dans ce wiki : l'envoi. Recopier vos nouvelles versions enregistrées sur le dépôt en ligne. Chaque envoi passe par votre accord. Voir : le dépôt en ligne.

R

recette
Dans le pack Next.js : une fonction courante prête à l'emploi et vérifiée chaque semaine, comme la connexion, l'envoi d'e-mails ou le paiement. Voir : le pack Next.js et ses recettes.
relecture (en anglais : review)
L'examen d'une tâche par des assistants qui ne l'ont pas écrite : ils relisent le code et essaient l'appli. Voir : /pulse:review.
retour arrière (en anglais : rollback)
Remettre en ligne la version précédente du site quand la nouvelle pose problème. La marche à suivre est notée dans docs/technical.md.

S

scénario
Dans une spec : un exemple précis de ce qui doit se passer, écrit en « Étant donné… lorsque… alors… ». Les tests automatiques vérifient ces scénarios.
secret
Toute information qui permet d'agir à votre place : clé d'API, mot de passe, jeton. Le test : quelqu'un qui la lit peut-il se faire passer pour vous ? Voir : les clés secrètes, /pulse:secrets.
session
Une conversation avec Claude Code, de son ouverture à sa fermeture (ou à /clear). À chaque nouvelle session, l'IA relit les règles et la mémoire du projet.
sous-agent
Voir : assistant.
spec (de « spécification »)
Le document qui décrit précisément ce qu'une user story doit permettre : écrans, informations, règles, scénarios. Verrouillée une fois validée. Voir : la spec, /pulse:spec.
squelette
Voir : projet de départ.

T

tâche
Une petite étape d'un plan, numérotée T1, T2, T3…, qui livre une seule chose que vous pouvez voir et tester. Voir : la réalisation, tâche par tâche.
terminal
Une fenêtre où l'on tape des commandes en texte au lieu de cliquer. Sous Windows, on y trouve PowerShell. Voir : ouvrir un terminal.
test automatique
Un petit programme qui vérifie tout seul que l'appli fait ce que la spec demande. À chaque changement, il prévient si quelque chose casse. Voir : /pulse:test.

U

user story (en abrégé : US)
Un besoin décrit du point de vue de l'utilisateur : « En tant que… je souhaite… afin de… », avec ses critères d'acceptation. Voir : la user story, /pulse:us.

V

variable d'environnement (en anglais : environment variable)
Un réglage nommé, comme SMTP_PASSWORD, que l'appli lit au démarrage. Sur votre ordinateur, ces réglages sont dans .env ; en ligne, chez l'hébergeur. Les secrets en font partie.
Vercel
Un hébergeur de sites et d'applis web, utilisé par le pack Next.js. Il publie le site à chaque envoi sur la version principale. Voir : les prérequis.
version enregistrée
Une photo datée de votre projet, avec une légende. En anglais : commit.
version parallèle
Une copie du projet où l'on avance sans toucher à la version principale. En anglais : branch.
version principale
La version du projet que le site publie. Le travail des versions parallèles la rejoint quand vous l'acceptez. Souvent nommée main.
VS Code (Visual Studio Code)
Un éditeur gratuit pour ouvrir et modifier les fichiers d'un projet. Avec l'extension Claude Code, c'est la façon conseillée de travailler avec Pulse. Voir : les prérequis.

W

worktree
Dans ce wiki : le dossier à part. Un deuxième dossier du projet, sur sa propre version parallèle. Voir : la version parallèle et le dossier à part.
