# Pack Pulse Next.js – pour les tests

- **Vitest** (`npm test`) : environnement Node ; fichiers `*.test.ts` dans un sous-dossier `__tests__/` du dossier testé ; alias `@app` vers `app/` et `@src` vers `src/`. Les règles et les use-cases (`src/core/`) se testent en unitaire, avec des doublures en mémoire des ports ; les repositories (`src/db/`) en intégration sur PGlite ; les actions, queries et containers par Playwright.
- **Base de test : PGlite** (Postgres en mémoire, `@electric-sql/pglite` et `drizzle-orm/pglite`) : une base neuve par fichier de test, migrations de `drizzle/` appliquées au départ, puis passée en paramètre aux fonctions (`db: Db`). L'aide `tests/helpers/base-de-test.ts` la prépare. La base Neon reste hors des tests.
- **Actions** : la logique se teste par sa règle ou son use-case (unitaire, doublures en mémoire). Le refus quand la donnée appartient à quelqu'un d'autre (`@securite`, filtre `utilisateurId`) se vérifie dans le test d'intégration du repository (PGlite). L'action elle-même (session, validation, résultat) se teste dans `e2e/`, car `actionConnectee` lit la session par `getAuth().api.getSession`.
- **Services externes** (e-mail, paiement, fichiers) : doublés aux frontières (`vi.mock` du module `src/adapters/<service>/<service>.adapter.ts`) ; en bout en bout, Mailpit pour l'e-mail.
- **Variables** : `vitest.config.ts` saute la validation de `env` (`SKIP_ENV_VALIDATION`) : un module importé sans simulation reçoit alors les valeurs brutes de `process.env`, sans valeur par défaut. Un test qui a besoin de valeurs simule le module (`vi.mock("@src/config/env", () => ({ env: { … } }))`, accesseur `get NOM() {…}` pour une valeur qui change d'un test à l'autre). Pour vérifier la validation elle-même : `chargerEnvValide()` de `tests/helpers/env-de-test.ts`.
- **Playwright** (`npm run test:e2e`) : dossier `e2e/`, projets « ordinateur » et « telephone » ; première fois : `npx playwright install chromium`. En local il lance `npm run dev` ; en CI, `npm run build && npm run start`.
- **Accessibilité de chaque page** : le test `e2e/` d'une nouvelle page (ou d'un nouvel écran) appelle `verifierAccessibilite(page, testInfo)` de `e2e/aides/accessibilite.ts` une fois la page dans son état principal (formulaire affiché, liste chargée) : aucune violation WCAG 2.2 AA (axe), boutons et champs de 44 px au moins sur téléphone.
- Titre de chaque test tiré d'un scénario : `US-003-1 – <titre de l'exemple>`.
