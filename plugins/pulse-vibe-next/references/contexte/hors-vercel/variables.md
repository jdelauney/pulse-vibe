# Pack Pulse Next.js – variables d'environnement sur le serveur

Affiché pour `/pulse:secrets` et pour la mise en ligne (`pulse-aidd pile contexte deploy-variables`), hébergements `docker` et `serveur`.

- **Où** : le fichier `.env` du dossier du site, sur le serveur (`chmod 600`, jamais dans Git). Docker : lu au démarrage des conteneurs (`env_file` de `compose.production.yml`). Serveur : lu par le service du site (`EnvironmentFile`) et à la construction.
- **Saisie par la personne** : elle ouvre le fichier sur le serveur (`nano .env`, dans sa session SSH) et y colle la valeur ; la valeur ne passe jamais par la conversation. `pulse-aidd secrets envoyer` et `generer --envoyer` n'écrivent pas sur le serveur : ils disent quoi faire (code 3 de l'adaptateur). Une valeur à tirer au hasard (`BETTER_AUTH_SECRET`, `FORMULAIRE_SECRET`, mot de passe de la base) se tire sur le serveur : `openssl rand -hex 32`, puis la personne la colle dans `.env`. Une valeur venue d'un fournisseur (clé Stripe, mot de passe SMTP) se copie depuis son tableau de bord, ou depuis `.env.envoi` sur l'ordinateur, puis la ligne de `.env.envoi` se vide.
- **Quelles variables** : celles de `.env.example`, plus les lignes propres au serveur de la fiche de l'hébergement (`PULSE_ENV`, `SITE_URL`, base). Chaque variable obligatoire de `src/config/env.ts` est saisie : la validation t3 env arrête le démarrage (docker) ou la construction (serveur) où l'une manque.
- **Une seule production** : pas de prévisualisation chez cet hébergeur ; les essais avec un SMTP de test et des clés de test (Stripe `sk_test_…`) se font sur l'ordinateur, avec `.env`.
- **Une variable modifiée sert après un redémarrage** : docker, `./scripts/deployer.sh` ; serveur, `systemctl --user restart <nom du paquet>`. `pulse-aidd secrets redeployer` rappelle la commande.
- **Inventaire** : `pulse-aidd secrets inventaire` ne lit pas le serveur (colonnes de l'hébergeur à « ? »). Les noms présents sur le serveur, sans les valeurs : `cut -d= -f1 .env`, tapé par la personne.
- **Comptes du serveur** : la clé SSH de l'ordinateur (renouveler : nouvelle clé ajoutée à `~/.ssh/authorized_keys` du serveur, essai, puis l'ancienne retirée) ; la clé de déploiement GitHub du serveur (lecture seule : GitHub → le dépôt → Settings → Deploy keys) ; le compte chez le fournisseur, avec la validation en deux étapes. Traces : `last` et `journalctl -u ssh` sur un VPS (compte administrateur), l'historique des connexions chez le fournisseur.
