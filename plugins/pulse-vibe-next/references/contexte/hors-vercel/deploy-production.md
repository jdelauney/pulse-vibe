# Pack Pulse Next.js – mode production sur un serveur

- **better-auth** (recette connexion) : `BETTER_AUTH_URL` = l'adresse du site en production, dans le `.env` du serveur.
- **Adresse du site** : `SITE_URL` (ex. `https://www.mon-site.fr`) dans le `.env` du serveur, obligatoire ; elle sert aussi à la construction (pages préparées d'avance, sitemap).
- **Retour arrière** : « Retour arrière » de la fiche de l'hébergement (`pulse-aidd pile reference hebergement-docker.md` ou `hebergement-serveur.md`), recopié dans `docs/technical.md` du projet.
- **Essai du retour arrière** (`deploy/production.md` § 7), quand le site a déjà été mis en ligne au moins deux fois : sur le serveur, `./scripts/deployer.sh retour` ; vérifier `pulse-aidd sonder <adresse>/api/sante` ; puis `./scripts/deployer.sh` remet la dernière version de `main` ; vérifier de nouveau. Données : la personne affiche seulement `ls sauvegardes/` et relit la commande de restauration de la fiche, sans restaurer.
- Construction avec les contrôles (`/pulse:deploy` § 5.1, quand la CI ou le mode production sont ajoutés) : docker, dans `Dockerfile`, la ligne `RUN node scripts/verifier.js && npm run check && npm run typecheck` juste avant `RUN npm test` ; serveur, dans `scripts/deployer.sh`, les mêmes commandes juste avant `npm test`.
- Surveillance (`/pulse:deploy` § 5) :
  - **Sonde de disponibilité** : sur `<adresse>/api/sante`, qui répond 503 quand la base ne répond plus. Base sur le serveur : toutes les 5 à 15 minutes. Base Neon : toutes les 15 à 30 minutes (la réponse « ok » est gardée 15 minutes par le site ; Neon se met en veille entre deux appels). La sonde prévient la personne par e-mail.
  - **Journaux** : `./scripts/deployer.sh journal` sur le serveur (docker : `docker compose logs` ; serveur : `journalctl --user`). On y trouve les erreurs du serveur (le `logger` du squelette les écrit sur la sortie d'erreur) et celles du navigateur (message « Erreur dans le navigateur »). La référence affichée à la personne (`digest`) se cherche avec `./scripts/deployer.sh journal | grep <référence>`. Docker garde 5 fichiers de 10 Mo (`compose.production.yml`, `logging`) ; systemd, selon la place réservée au journal sur le serveur.
  - **Le serveur** : mises à jour de sécurité automatiques (`unattended-upgrades`) ; un redémarrage demandé (`/var/run/reboot-required` existe) se fait à une heure creuse, puis vérifier `/api/sante`. Docker : chaque mise en ligne reprend la dernière image Node.js et PostgreSQL de la même version.
  - Limites : aucune alerte sur le nombre d'erreurs ; la place sur le disque se surveille (`df -h`), les copies de la base comprises.
