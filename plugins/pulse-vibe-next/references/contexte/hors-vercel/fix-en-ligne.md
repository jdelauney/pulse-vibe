# Pack Pulse Next.js – corriger un problème du site en ligne, sur un serveur

Les commandes du serveur se tapent par la personne, dans sa session SSH, depuis le dossier du site.

- **Constater** : la sonde vise `<adresse>/api/sante`, qui répond 200 quand la base répond et 503 sinon. Un 503 oriente vers la base : docker, `docker compose -f compose.production.yml ps` (état du conteneur `db`) ; serveur, `systemctl status postgresql` ; Neon : limite de l'offre gratuite, adresse changée. Le site ne répond plus du tout : le service du site (docker, `ps` ci-dessus ; serveur, `systemctl --user status <nom du paquet>`), puis Caddy ou le proxy du fournisseur.
- **Journaux** : `./scripts/deployer.sh journal` (docker : `docker compose logs` ; serveur : `journalctl --user`). La référence montrée à l'écran par la page d'erreur (`digest`) : `./scripts/deployer.sh journal | grep <référence>`. Le message d'une erreur de la base peut citer une valeur saisie par un visiteur : ne recopier que le type d'erreur. Caddy : docker, `docker compose -f compose.production.yml logs caddy` ; serveur, `journalctl -u caddy` (compte administrateur).
- **Depuis la dernière mise en ligne** : `git log -1` (la version récupérée) ; docker, `docker image ls` (dates des images) ; serveur, `ls versions/` et `readlink courante`. Une mise en ligne en échec laisse la version d'avant en ligne (le problème vient alors d'ailleurs).
- **Contenir** : `./scripts/deployer.sh retour` remet la version d'avant ; il ne touche pas la base. Une migration appliquée reste appliquée : l'ancienne version doit pouvoir lire la base telle qu'elle est (migrations en deux mises en ligne).
- **Causes fréquentes propres au serveur** : variable absente ou mal écrite dans le `.env` du serveur, `BETTER_AUTH_URL` ou `SITE_URL` différente de l'adresse réelle (connexion qui échoue), disque plein (`df -h` : anciennes copies de `sauvegardes/`, images Docker : `docker image prune`), mémoire (`free -h`), certificat HTTPS non obtenu (domaine qui ne pointe pas vers le serveur, ports 80 et 443 fermés), site arrêté après un redémarrage du serveur (serveur : `loginctl enable-linger` manquant), limite d'un service gratuit atteinte (Neon, fournisseur d'e-mail).
- **Après la correction** : envoyer le correctif sur `main`, puis `./scripts/deployer.sh` ; vérifier `/api/sante` de nouveau.
