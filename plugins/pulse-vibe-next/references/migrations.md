# Pack Pulse Next.js – mettre à niveau un projet plus ancien

Notes lues par `/pulse:init` (« Mettre à niveau un projet Pulse plus ancien »), et seulement là. Chaque note commence par la version du pack qui a apporté le changement, puis le signe qui le révèle dans le projet : une note dont le signe est absent ne s'applique pas. Les notes s'appliquent de la plus ancienne à la plus récente, avec l'accord de la personne, puis `npm run check && npm run typecheck && npm test`.

- **Projet créé avant pulse-vibe-next 0.9.0** (`next.config.ts` sans objet `sources`) : reprendre `next.config.ts` du squelette (constantes `sources`, `csp`, `entetesDeSecurite` et fonction `headers()`), en gardant les autres réglages du projet.
- **Projet créé avant pulse-vibe-next 0.11.0** (`envServeur()`, `src/db/index.ts`) : `npm install @t3-oss/env-nextjs`, reprendre du squelette `src/config/env.ts`, `src/config/env-public.ts`, `src/config/env-commun.ts`, `src/db/db-client.ts`, `tests/helpers/env-de-test.ts` et le réglage `env` de `vitest.config.ts` ; reporter les variables du projet dans `server` d'`env.ts` (secrets) ou dans `client` + `experimental__runtimeEnv` d'`env-public.ts` (publiques, lues par `envPublic` dans les composants client), et les vérifications croisées dans le `createFinalSchema` d'`env.ts` ; supprimer `src/db/index.ts` ; remplacer `envServeur().X` par `env.X` et `@src/db` par `@src/db/db-client` ; dans les tests, `{ envServeur: () => ({…}) }` devient `{ env: {…} }`.
- **Projet créé avant pulse-vibe-next 0.17.0** (pas de `scripts/migrer.mjs`) : reprendre du squelette `scripts/migrer.mjs`, `tests/migrer.test.ts`, `vercel.json`, `drizzle.config.ts`, `instrumentation.ts`, `src/lib/errors/erreur-de-requete.ts` (et son test), `src/lib/logger.ts`, `app/error.tsx`, `app/global-error.tsx`, `e2e/accueil.spec.ts`, et le lien d'évitement de `app/layout.tsx` (balise `<a href="#contenu">` et `<div id="contenu">`) ; dans `src/lib/safe-action.ts`, reprendre `defineMetadataSchema`, `handleServerError` et le `.use()` du squelette en gardant `actionConnectee`, puis donner un nom à chaque action (`.metadata({ nom: "…" })` : `npm run typecheck` liste celles qui en manquent) ; `npm uninstall ws @types/ws next-themes`, `npm install -D @axe-core/playwright`, `shadcn` passé en `devDependencies`, `"engines": { "node": ">=22.19.0" }` dans `package.json` ; `.gitattributes` (`* text=auto eol=lf`) et `.npmrc` (`save-exact=true`) ; dans `src/components/ui/sonner.tsx`, `theme="light"` à la place de `useTheme()`. Puis séparer la base de développement de la production (« Mise en place » et « Pour mettre en ligne » du pack).
