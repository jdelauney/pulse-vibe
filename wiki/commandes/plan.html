Étape 3 · Préparer

/pulse:plan

Concevoir comment réaliser la spec d'une user story (pile, données, écrans, sécurité, fichiers), puis la découper en petites tâches ordonnées, chacune testable à l'écran (une spec = un plan, rangé à côté de sa spec), écrit une fois validé avec vous.

    Description

    Le plan décide comment construire ce que la spec demande, puis le découpe en petites tâches numérotées : T1, T2, T3… « On avance par petites tâches que vous pouvez tester une par une : l'IA se trompe moins, et vous gardez le contrôle. »

    D'abord la conception : les outils utilisés, l'adresse de chaque écran, où sont gardées les informations et où l'on vérifie qui a le droit d'y toucher, les clés secrètes, les points de sécurité, les fichiers à créer. Ensuite les tâches : chacune livre quelque chose que vous pouvez voir et tester en moins de 2 minutes.

    Le plan sert aussi de tableau de suivi : [ ] à faire, [~] en cours, [x] terminé. Une fois validé, Pulse écrit votre carnet de route, avec les commandes à copier tâche par tâche.

    Pourquoi l'utiliser

    • Vous testez à chaque étape. Chaque tâche livre un résultat visible, du cas normal vers les cas d'erreur et les règles d'accès.
    • La sécurité est pensée avant le code. Chaque règle importante est vérifiée côté serveur ; une protection exigée par la sécurité vous est expliquée.
    • Vous savez ce qui vous revient. Une action à faire vous-même (créer un compte, saisir une clé) est signalée dans sa tâche.
    • Un carnet de route toujours à jour. docs/guide/index.md vous dit quelle commande taper ensuite.

    Quand l'utiliser

    1. 1 Démarrer
    2. 2 Décrire
    3. 3 Préparer
    4. 4 Construire
    5. 5 Mettre en ligne
    6. 6 Être trouvé
    7. 7 À tout moment
    • Après /pulse:spec, une fois la spec verrouillée.
    • Après /pulse:ui maquettes, si vous avez maquetté les écrans : le plan cite la maquette retenue.
    • Avant /pulse:implement ou /pulse:spirc, qui réalisent les tâches.

    Avec le pack Next.js : le plan donne l'adresse de chaque écran, les colonnes de chaque table et la règle qui vérifie à qui appartient chaque information. Les tâches suivent un découpage type : la table, la règle métier, la lecture, l'écriture, puis le test du parcours complet. Une recette apporte ses tâches prêtes, reprises dans la suite des numéros avec la mention « Recette : connexion » ; la connexion passe avant toute user story qui a des données personnelles, et la recette de référencement avant la mise en ligne d'un site à trouver.

    Comment la lancer

    /pulse:plan <US-XXX [US-YYY…] | chemin de la spec>

    Entre crochets [ ] : facultatif. Entre chevrons < > : à remplacer par votre valeur. La barre | sépare les choix possibles.

    • Un numéro de user story (US-001) : le plan de sa spec.
    • Plusieurs numéros : un plan par user story, l'un après l'autre, dans l'ordre du parcours.
    • Le chemin d'une spec : le plan de cette spec.
    • Sans rien : Pulse liste les specs, en premier celles qui attendent leur plan, et vous demande laquelle traiter.
    /pulse:plan US-001
    /pulse:plan

    Ce qu'elle produit

    FichierÀ quoi il sert
    aidd_docs/tasks/<groupe>/PLAN-SPEC-US-XXX-<nom>.mdLe plan, à côté de sa spec : la conception technique, puis les tâches, chacune avec son objectif, ce dont elle dépend, ses fichiers, la vérification à faire à la main et les tests automatiques.
    docs/guide/Votre carnet de route : les commandes à copier, tâche par tâche. Il se met à jour tout seul.

    La ligne « En parallèle avec » des autres plans est mise à jour quand deux user stories peuvent avancer en même temps. Une fonctionnalité en plus, demandée pendant la validation, est notée « En attente » dans docs/prd.md.

    Risques et précautions

    • Cette commande écrit seulement des documents. Le code viendra avec la réalisation des tâches.
    • Le plan est écrit après votre validation. Si vous demandez un changement, Pulse vous montre ce qui change, puis redemande.
    • La spec reste intacte. Le plan la lit sans la modifier ; un comportement qu'elle ne prévoit pas vous est présenté comme un ajout proposé.
    • Un nouvel outil vous est demandé. Pulse en introduit un seulement avec votre accord. Un paiement s'intègre d'abord en mode test.

    Attention : repérez les lignes « Action manuelle » dans les tâches. Elles vous demandent un geste (créer un compte, saisir une clé chez l'hébergeur) ; écrivez toujours une clé secrète directement dans le fichier local, jamais dans la conversation.

    Problèmes et solutions

    Pulse me propose de terminer la spec d'abord

    La spec est absente, ou encore en brouillon avec des questions en suspens. Le plan s'appuie sur une spec verrouillée : lancez /pulse:spec US-001, puis revenez au plan.

    Pulse me dit qu'il manque les choix techniques

    Le plan a besoin de docs/technical.md pour savoir comment construire. Lancez /pulse:tech.

    Le plan a trop de tâches

    Pulse vise 1 à 4 tâches par user story. Au-delà, il le signale et propose de découper la user story en deux avec /pulse:us, puis une spec et un plan pour chacune.

    Je veux ajouter une fonctionnalité au plan

    C'est un changement de périmètre : Pulse la note « En attente » dans le PRD. Une fois le plan écrit, /pulse:refine l'ajoutera.

    Un plan existe déjà avec des tâches terminées

    Pulse le garde tel quel, et vous propose seulement d'ajouter ou de réordonner les tâches restantes.

    Exemples

    /pulse:plan US-001

    Conception : les rendez-vous sont gardés sur le serveur ; une cliente voit et modifie seulement les siens, vérifié côté serveur. Tâches : T1 Afficher la page des créneaux · T2 Réserver un créneau et le voir confirmé · T3 Refuser un créneau déjà pris. Ajout exigé par la sécurité : protéger le formulaire de réservation, ouvert à tous, contre les envois en masse. → Valider le plan (Recommandé) / Je veux changer quelque chose

    Valider le plan

    pulse-aidd guide

    Votre carnet de route est dans docs/guide/index.md ; il se met à jour tout seul. Prochaine étape : /pulse:spirc US-001, ou /pulse:implement US-001 T1 pour la première tâche seulement.

    /pulse:plan US-003

    La spec du rappel par e-mail est encore en brouillon : une question reste ouverte. Je vous propose de la terminer d'abord avec /pulse:spec US-003.

    Commandes liées

    • /pulse:spec : verrouiller la spec sur laquelle s'appuie le plan.
    • /pulse:ui : maquetter les écrans avant le plan.
    • /pulse:refine : changer le plan selon vos remarques.
    • /pulse:implement : réaliser une tâche et comprendre son code.
    • /pulse:spirc : enchaîner réalisation, relecture et enregistrement, tâche par tâche.
    • /pulse:guide : savoir quelle commande taper maintenant.
