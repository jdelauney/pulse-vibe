/pulse:auto-fix

Faire passer au vert tous les contrôles automatiques du code (syntaxe, règles d'écriture, types, formatage), en confiant les corrections à des agents en parallèle.

    Description

    Votre projet a des contrôles automatiques : ils relisent le code comme un correcteur d'orthographe (syntaxe, règles d'écriture, types, mise en forme). /pulse:auto-fix les lance, rassemble toutes les erreurs, puis confie les corrections à plusieurs assistants qui travaillent en même temps.

    Chaque assistant reçoit au plus 5 fichiers, et chaque fichier va à un seul assistant. Les corrections faites, Pulse relance les contrôles et recommence avec les erreurs restantes, 3 cycles au plus. Le comportement de votre appli reste le même.

    La commande cherche aussi les clés secrètes écrites par erreur dans le code. Celles-là ne sont pas confiées à un assistant : vous les mettez à l'abri ensemble.

    Pourquoi l'utiliser

    • Plus d'erreurs rouges, sans effort. Toutes les erreurs que les contrôles repèrent seuls sont corrigées d'un coup.
    • Rapide. Plusieurs assistants corrigent en même temps, chacun sur ses fichiers.
    • La sécurité est préservée. Une correction ne désactive jamais un contrôle, n'ouvre pas l'accès à tous et ne supprime pas le code qui pose problème.
    • Les erreurs restantes sont expliquées. En langage simple, avec l'action proposée.

    Quand l'utiliser

    7. 7 À tout moment

    • Après /pulse:implement, s'il reste beaucoup d'erreurs : Pulse vous la propose.
    • Avant /pulse:review ou /pulse:commit, pour partir d'un code propre.

    Conseil : cette commande complète la relecture et votre test, sans les remplacer. Un code sans erreur rouge peut encore faire autre chose que ce que vous voulez.

    Comment la lancer

    /pulse:auto-fix [--detail]

    Entre crochets [ ] : facultatif. Entre chevrons < > : à remplacer par votre valeur. La barre | sépare les choix possibles.

    • Rien : les contrôles, les corrections, puis le rapport résumé.
    • --detail : le même travail, avec la liste de chaque correction dans le rapport.
    /pulse:auto-fix
    /pulse:auto-fix --detail

    Le rapport indique les erreurs corrigées, celles qui restent, le nombre de cycles et les fichiers modifiés par cette commande seulement. L'enregistrement se fait ensuite avec /pulse:commit.

    Risques et précautions

    • Pulse s'en tient aux contrôles déclarés dans docs/technical.md, section « Commandes du projet ».
    • Un outil manquant s'installe seulement avec votre accord.
    • Une correction qui changerait le comportement de l'appli se décide avec vous. Par exemple : une fonction attend un nombre et reçoit un texte.

    Risque : une clé secrète trouvée dans le code doit être mise à l'abri dans le fichier local de vos clés. Si elle a déjà été envoyée sur le dépôt en ligne, elle doit aussi être révoquée chez le fournisseur : /pulse:secrets fuite vous guide.

    Problèmes et solutions

    « Aucune commande de contrôle n'est déclarée »

    Seul le contrôle des clés secrètes a pu tourner. Ajoutez des contrôles à votre projet avec /pulse:tech.

    « Les choix techniques manquent »

    La commande lit la liste des contrôles dans docs/technical.md. Lancez d'abord /pulse:tech.

    Un contrôle échoue parce que l'outil n'est pas installé

    Pulse vous le signale et propose la commande d'installation du projet. Acceptez, puis il relance les contrôles.

    Il reste des erreurs après 3 cycles

    Pulse s'arrête et explique chaque erreur restante en langage simple, avec l'action proposée. Souvent, la corriger changerait le comportement : décidez avec lui.

    Commandes liées

    • /pulse:review : la relecture de la tâche et votre test, après les corrections.
    • /pulse:commit : enregistrer les corrections.

    • /pulse:secrets : savoir où sont vos clés, ou réagir à une fuite.
    • /pulse:tech : déclarer les contrôles automatiques du projet.
